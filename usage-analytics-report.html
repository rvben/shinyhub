A successful live connection—not a page request.

Shiny apps are interactive WebSocket applications. Recording after the proxy’s successful upgrade excludes assets, probes, waiting-page polls, and failed launches. Reloads and reconnects intentionally begin new sessions.

Configurable granularity, enforced before write.

The common pattern is implemented as a privacy ladder: disabled, unattributed, pseudonymous, or identified. The hub sets the maximum granularity; each app may be stricter. The safe default is unattributed. Pseudonymous data is still personal data—not anonymized—and every usage response is marked Cache-Control: no-store.

Best-effort analytics with visible failure signals.

After each successful WebSocket upgrade, policy resolution uses an in-memory snapshot, so connection establishment performs no analytics database query. The snapshot refreshes every 30 seconds for HA policy changes and slug reuse, while every queued insert independently clamps identity against current durable policy. A stale cache can temporarily undercount after collection is loosened, but it cannot retain identity above the committed ceiling. Persistence remains asynchronous through a bounded recorder that absorbs bursts, retries transient failures, and preserves close events. ShinyHub calculates and retains historical peak concurrency itself; Prometheus is only an optional one-way export of live and health signals.
